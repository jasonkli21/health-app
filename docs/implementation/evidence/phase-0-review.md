# Phase 0 scaffold review

Review date: 2026-10-03. Scope: repository foundation fixes and documentation-only Phase 1–9 planning. No domain tables, product screens, AI behavior, native health integrations, cloud deployment, or web client were implemented.

Read every authored repository file, including CODEX/handoff/planning standard; product and five-surface UX; layering, canonical ownership, all seven accepted ADRs; relational/JSONB/time/provenance model; API contract direction; privacy and Personal AI boundary; local/cloud setup; primary and deferred web roadmaps; placeholders, manifests, CI and scripts. ## Issues and corrections

- Expo Router's required support dependencies were missing; React types targeted 19.1 while React is 19.2. Added SDK-compatible packages/types, aligned TypeScript to ~6.0.3 after the online Expo check and removed deprecated baseUrl, and pinned native animation/worklet and Metro peers after resolving incompatible automatic peer selections. Kept SDK 57/RN 0.86.3/React 19.2.3. `react-dom` satisfies Router/runtime transitive peers; there is still no web app or web platform configuration. Version evidence: [Expo SDK reference](https://docs.expo.dev/versions/v57.0.0/), [Router installation](https://docs.expo.dev/router/installation/), and installed Expo 57.0.26 `bundledNativeModules.json`.
- `start --dev-client` assumed a development client that was not installed. Phase 0 now starts Expo Go. Removed redundant SDK `newArchEnabled` configuration. Native development builds remain Phase 8 scope.
- No pnpm lock meant CI cache setup/install could fail or drift. Added `pnpm-lock.yaml`, exact pnpm 9.15.0/Node minimum declarations, and frozen CI/local installs. Added API transitive constraints for the tested Python baseline and pinned Hatchling build tooling. Python constraints have documented platform limits.
- Formatting was a successful echo; JS lint and mobile tests were absent from CI. Added real Prettier/ESLint checks, Python format checking, explicit nested Python config paths (root invocation otherwise misses strict settings), and the transparent mobile no-test hook. Formatted scaffold/docs. No implementation-mirroring tests added.
- Verifier only checked a few paths/two JSON files. Extended required foundations, TOML/JSON checks, test location and shared-native boundary checks. It is a lightweight guard, not a transitive import resolver/security audit.
- Local Postgres's trivial dev password was exposed on every network interface. Restricted the host binding to 127.0.0.1 and documented disposable local credentials.
- Environment examples implied functioning integrations/settings. Marked them planned and server-only; documented that `/healthz` is liveness independent of DB/AI/auth and there are no mobile API requests yet. Added physical-device networking and data-preserving shutdown guidance.
- API client generation was a successful echo. It now fails clearly until Phase 1 implements it. Package READMEs remain honest placeholders; no duplicate DTOs were created.
- Broad `data/` ignore could conceal future fixtures. Retained the specific `.data/` runtime ignore and removed the broad rule.
- This directory has **no Git repository**. No Git initialization, commits, PRs or diff-based verification were attempted. The supplied `.github` workflow is ready for a later Git-backed repository, but hosted CI has not run.
