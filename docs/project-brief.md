# Product brief

## Vision

Build a comprehensive personal health application that can represent common and highly individualized health information without reducing the user's context to either a rigid medical questionnaire or an unstructured text blob.

The product should help a person understand and improve diet, exercise, sleep, recovery, symptoms, habits, medications/supplements, measurements, and other lifestyle/health concerns using one coherent personal-health model.

## Product principles

1. **Structured by default, extensible by design.**
2. **Everything is optional.** Missing data is unknown, never silently zero/false.
3. **Time is first-class.**
4. **Profile and daily state are different.**
5. **Temporary context can override baseline context.**
6. **AI assists structure rather than replacing it.**
7. **Canonical health state belongs to the Health app.**
8. **Recommendations should be explainable and actionable.**
9. **User control is mandatory.**
10. **Avoid premature platform complexity.**
11. **Mobile first, web extensible.** The initial product focuses on mobile/iOS, while backend and frontend boundaries must preserve a later high-quality desktop/web client without requiring a second health backend.

## Core product surfaces

- Today
- Plan
- Assistant
- Insights
- Profile

## Primary domains

Initial domain support should cover nutrition, exercise, sleep, symptoms, measurements, medications/supplements, habits, goals, active contexts, and custom trackers. Specialist depth is deliberately deferred.

## Success criteria

The first meaningful release should allow a user to build a useful profile, log structured daily information, define plans/trackers, ask context-aware questions, inspect transparent trends, and approve/reject AI-proposed changes.
